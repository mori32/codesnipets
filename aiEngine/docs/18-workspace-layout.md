# 作業データとビルド生成物の配置ルール

大きなデータや中間生成物をソースコードと分離し、各データの出所・用途・削除可否をいつでも判別できるようにする。

## 配置先

| 種別 | 配置先 | 例 |
|---|---|---|
| 一時データ、中間ファイル、キャッシュ、再生成可能な作業DB | `E:\lmwork-int\<目的フォルダ>\` | `E:\lmwork-int\tagged-corpus-trigram\` |
| 次工程で使う入力、検証済み成果物、再利用する大容量データ | `E:\lmwork-target\<目的フォルダ>\` | `E:\lmwork-target\tagged-corpus-trigram\` |
| ソースコード、ドキュメント、スクリプト、小さなテストfixture | `D:\Git\codesnipets\aiEngine\` | リポジトリ内 |
| 実行可能コードのビルド生成物 | `aiEngine` 内を唯一の例外として許可 | Cargo の `target\`、コード用CMake build出力 |

原則は「データのビルドはリポジトリの外、コードのビルドは `aiEngine` 内」。コーパス、ダンプ、モデル、辞書データ、ID列、ngram、学習checkpoint、分析DB、巨大ログは、最終的に次工程で使うかどうかに応じて `lmwork-int` または `lmwork-target` に置く。実行可能コードのビルド生成物以外の生成データを `aiEngine` 内に作らない。

## 既存データの固定許可リスト

移動・コピーができない既存データに限り、次の6ディレクトリをリポジトリ内に残すことを許容する。このリストは固定で、追加のデータ用ディレクトリを `aiEngine` 内に作らない。

- `corpus\wiki-ja\chunked` — ページ別チャンク
- `corpus\wiki-ja\clean-split` — 内容のあるページだけを抽出したデータ
- `corpus\wiki-ja\tagged-mecab-initial` — MeCabによる初期tagged corpus
- `dictionary\additions` — 最新追加単語
- `dictionary\build` — 最新ビルド済みユーザー辞書
- `dictionary\candidates` — 最新追加単語の旧候補データ

許可リストは既存データを移動・削除する指示ではない。これらには各READMEに記載した用途のcanonical dataだけを置き、別runの複製、古い版の追加蓄積、cache、ログ、補助出力を増やさない。「最新」データの更新・差し替え以外の生成物は `lmwork-int` / `lmwork-target` に出す。実行可能コードのビルド生成物は、これとは別に `aiEngine` 内で許可される唯一の生成物。

作業中の一時出力は `lmwork-int` に置く。検証が済み、次工程から参照する成果物だけを `lmwork-target` に置く。外部から取得して繰り返し使う正本データも、由来とハッシュを記録して `lmwork-target` に置く。必要なら目的フォルダ内で `source`、`work`、`output` のように分ける。

## README.md の必須記録

`README.md` の作成が必須なのは、`E:\lmwork-int\<目的フォルダ>\README.md` と `E:\lmwork-target\<目的フォルダ>\README.md` のみ（両ルートから1階層下）。2階層目以降のサブフォルダには作成を要求しない。サブフォルダやrunごとの目的・入力・生成物・状態・削除可否は、1階層下のREADMEにまとめて記録する。ルートの既存READMEは索引として保持するが、ルートへの新規作成も必須ではない。既存の深い階層のREADMEはこの変更だけを理由に削除しない。

READMEには少なくとも次を記録する。

- **目的・状態**: 何の作業か、作成日、run ID、完了・作業中・保留の別
- **ソース**: 入力ファイルの絶対パス、取得元、対象範囲。大きな入力・重要な出力は可能ならSHA-256
- **生成物**: ファイル/サブフォルダごとの内容、件数やサイズ、生成段階
- **生成方法**: 実行したコマンドまたはスクリプト、主要な引数、コード/辞書/モデルの版
- **次の利用先**: どの工程が読むか、引き渡し済みか
- **削除可否**: 再生成可能か、削除前に停止・確認すべき依存関係、正本か否か

まだ存在しない出力は「未生成」、未検証の成果物は「未検証」と書く。READMEだけで正本データの所在や承認状態が不明にならないようにする。大容量処理を始める前にREADMEを作り、処理後に実際の出力と状態を更新する。

## 大容量作業領域の検索・走査制限

`E:\lmwork-int`、`E:\lmwork-target` とその配下は大容量データ領域として扱う。ユーザーが明示的に許可していない限り、これらのルートまたは目的フォルダ全体に対して、`rg`、`rg --files`、`Get-ChildItem -Recurse` などの再帰検索・列挙を実行しない。ファイル名だけの列挙もディレクトリ全体へのI/Oを起こすため対象とする。AIへの依頼・サブタスク・バックグラウンド処理にも同じ禁止を適用する。

必要な確認は、README・manifest・ledger・ログなど、目的フォルダのREADMEで指定された既知の小さな管理ファイルを個別に読む。データを検索する必要がある場合は、対象ファイル、検索語、読み込み範囲を限定したコマンドまたは専用のストリーミング処理を使い、`.bz2`、`.gz`、大容量JSONLやコーパス本文を無指定で走査しない。対象や処理量を限定できない場合は走査を始めず、ユーザーに範囲を確認する。

ソースコードの調査は `D:\Git\codesnipets\aiEngine` 内で必要なコード拡張子に絞って行い、`corpus`、データ、辞書build出力、生成物を除外する。作業領域全体をコード検索の対象に含めない。検索コマンドが意図せず広い範囲を列挙・読込した場合は直ちに中断し、実際の対象・経過時間・確認できた資源使用量を記録して報告する。

## 保持と削除

- `lmwork-int` は一時領域だが、稼働中のプロセスが使うファイルや再開に必要なcheckpointを実行中に消さない。削除時は対象の目的フォルダを特定し、プロセス停止と再生成可否をREADMEで確認する。
- `lmwork-target` は次工程が使うデータの保管場所。依存する工程がなく、正本・承認済みデータでもないと確認できるまで削除しない。
- ルートや複数目的フォルダをまとめて対象にする一括削除は行わない。削除はREADMEに記載された特定の対象に限定する。
- 既存のデータをこのルールだけを理由に自動移動・削除しない。移動が必要な場合は、使用中プロセス・参照先を確認し、コピー後にサイズとSHA-256を照合してから切替える。

## 既存ドキュメント中のパス

過去のrun記録や例にあるリポジトリ内の `target\`、`corpus\` 等のデータパスは、すでに実行した履歴を再現するための記録として残す。新しいrunではこの配置ルールを優先し、コマンドの入力・出力を `E:\lmwork-int` / `E:\lmwork-target` に明示的に向ける。履歴に記録されたファイルをこの規則だけで移動・削除しない。
